# BookNParty - AI Agent Instructions

## Project Overview

**BookNParty** is a full-stack venue booking platform built with Next.js 16.3.3, Prisma 7, and PostgreSQL. It enables venue owners to list their properties, customers to discover and book venues, and administrators to manage the platform.

## Current Status

- **Phase**: Phase 4 Planning/Execution (Phase 3 verified, payment deferred to Phase 5)
- **Production Ready**: Yes (manual booking confirmation flow active; payment pending)
- **Last Updated**: August 31, 2026

## Tech Stack

- **Framework**: Next.js 16.3.3 (App Router)
- **Database**: PostgreSQL with Prisma 7 ORM
- **Authentication**: NextAuth v5 (beta.32)
- **UI**: React 19.2 + Tailwind CSS 4 + Radix UI
- **Forms**: React Hook Form + Zod validation
- **Images**: Cloudinary via next-cloudinary
- **Node**: PostgreSQL adapter (@prisma/adapter-pg)

## Project Structure

```
src/
  app/               # Next.js App Router pages & API routes
    api/             # REST API endpoints
    dashboard/       # Role-based dashboards (admin, owner, customer)
    (auth)/          # Login/Register pages
    venues/          # Public venue browsing
  components/        # Reusable React components
  lib/               # Utilities (auth, prisma, utils)
prisma/
  schema.prisma      # Database schema
  seed.ts            # Database seeding
docs/                # Comprehensive documentation
```

## Key Conventions

1. **Authentication**: All protected routes check session role in API handlers
2. **Database Access**: Always use `prisma` from `@/lib/prisma` (singleton with Prisma Accelerate support)
3. **Forms**: Use React Hook Form + Zod resolver
4. **Styling**: Tailwind utility classes + SCSS for complex components
5. **API Pattern**: Route handlers return `NextResponse.json()` with proper status codes
6. **Server Components**: Default to Server Components; add `"use client"` only when needed

## Common Commands

```bash
# Development
npm run dev              # Start dev server (localhost:3000)
npm run build            # Build for production
npm run lint             # Run ESLint

# Database
npx prisma db push       # Sync schema to database (dev)
npx prisma generate      # Generate Prisma Client
npm run seed             # Seed database with test data
npx prisma studio        # Open Prisma Studio UI

# Deployment
npm run start            # Start production server
```


## User Roles

- **ADMIN**: Full platform access, user management, venue approval
- **OWNER**: Venue management, booking management, revenue analytics
- **CUSTOMER**: Browse venues, create bookings, submit reviews

## When Contributing

1. **Read the relevant doc** in `/docs` before making changes
2. **Maintain consistency** with existing patterns (check [ARCHITECTURE.md](docs/ARCHITECTURE.md))
3. **Test role-based access** for any auth-related changes
4. **Update database** with `prisma db push` after schema changes
5. **Check builds** with `npm run build` before committing

## Known Limitations
